GapScreener Scripts

Comprehensive guide to gap-screener trading pipeline scripts. Includes morning CSV generation, option quoting, EOD analysis, and real-time trade monitoring.

Overview

The GapScreener system is a two-phase daily trading pipeline designed to identify and execute gap-trading opportunities in index options. It operates in three stages:

Purpose: Automatically discover gap-up/gap-down opportunities in stocks, resolve nearest out-of-the-money options, and track intraday performance versus expected outcomes.

Key Components

  • Gap Screener (External): Chartink-based daily screener at /home/karthikeyan/tools/ohlc identifies gap candidates
  • Option Resolution: Resolves nearest OTM contracts from local NFO contract master (no network calls)
  • Quote Collection: Batches live quotes via ANT websocket for speed and efficiency
  • EOD Analysis: Validates trades against expected outcomes (option profit or directional breakout)
  • Live Monitoring: Bash-based real-time log parser for trade tracking

Daily Workflow

1
Morning (Pre-market): Run ./scripts/gapscreener-morning.sh
↓
2
Market Hours: Monitor trades with ./scripts/monitor-gap.sh
↓
3
EOD (After 3:30pm): Run ./scripts/gapscreener-eod.sh

Morning Pipeline

The morning phase generates the day's gap-screener CSV, resolves option contracts, fetches live quotes, and optionally places cover orders.

Script: gapscreener-morning.sh

Location & Invocation

./scripts/gapscreener-morning.sh
# Runs from repo root, spawns 3 npm scripts in sequence

Execution Flow

This script orchestrates three sequential steps:

  1. npm run gapscreener:generate – Generate gap-screener CSV
  2. npm run gapscreener:start – Resolve options and fetch morning quotes
  3. npm run gapscreener:coverorder – Place cover orders (config-gated, optional)

Step 1: Generate Screener CSV

npm run gapscreener:generate

Required

Invokes the external Chartink screener project at /home/karthikeyan/tools/ohlc and copies its output CSV locally.

Input

Runs the external screener project (no CLI args).

Output File

src/tools/gapscreener/gap-screener.csv with columns:

Column Type Description
Symbol string Stock symbol (e.g., RELIANCE, INFY)
Name string Company name
LTP number Current stock price at scan time
Recommendation Buy | Sell | (blank) Gap direction identified by screener
1st15m High number First 15-minute candle high
1st15m Low number First 15-minute candle low

Step 2: Start – Option Resolution & Morning Quotes

npm run gapscreener:start

Required

Reads gap-screener.csv, resolves nearest OTM option contract for each recommendation, and fetches live morning prices via ANT websocket.

Option Resolution Logic

  • For Buy recommendation: Nearest Call (CE) strike above current spot
  • For Sell recommendation: Nearest Put (PE) strike below current spot
  • Resolution source: Local NFO contract-master JSON (no network calls; instant)

Quote Collection

Batches all resolved option tokens into a single ANT websocket subscription (via src/tools/AntBatchQuote.ts) to fetch live prices efficiently:

Subscribes: token1, token2, ...
Waits for: First live tick for each
Returns: Map of token → LTP
Timeout: 3000ms (QUOTE_WAIT_MS)

Output File

src/tools/gapscreener/gap_screener_option_quote.csv with columns:

Column Type Description
ANT Stock Code string Stock symbol from gap-screener.csv
Stock Name string Company name
Option Quote number Morning purchase price from live quote
Option Contract string Trading symbol (e.g., RELIANCE25OCT1100CE)

Step 3: Cover Order (Optional)

npm run gapscreener:coverorder

Optional

Reads the morning-generated gap_screener_option_quote.csv and places ANT cover orders for each resolved contract.

Warning: ANT.placeCoverOrder has never been confirmed against a live AliceBlue response. Do not enable settings.gapScreenerCoverOrderEnabled against a real account without live testing in isolation first.

Config Gate

This step is a safe no-op unless settings.gapScreenerCoverOrderEnabled: true in config.yml.

Parameters (from config.yml)

  • settings.gapScreenerCoverOrderEnabled – Enable/disable this step
  • settings.gapScreenerUserId – User ID for order placement
  • settings.gapScreenerQuantity – Lot size per contract
  • settings.gapScreenerStopLossPoints – Stop-loss distance in points

EOD Pipeline

The end-of-day phase evaluates each morning's trade against expected outcomes and validates whether the gap trade was successful.

Script: gapscreener-eod.sh

Location & Invocation

./scripts/gapscreener-eod.sh
# Runs from repo root, spawns 1 npm script

Timing

Run after 3:30pm IST (after NSE/NFO market close). Earlier runs will fail because AliceBlue's websocket stops streaming ticks once the exchange session ends.

npm run gapscreener:end – EOD Analysis

Inputs

  • src/tools/gapscreener/gap_screener_option_quote.csv – Output from morning's gapscreener:start
  • src/tools/gapscreener/gap-screener.csv – Original gap-screener CSV (stock 1st15m levels)

Processing Steps

  1. Re-resolve each morning row's exact contract (using AntContractMaster.findByTradingSymbol, not a fresh nearest-OTM calculation)
  2. Fetch the contract's EOD live price via:
    • Before 3:30pm: ANT websocket batch subscribe (same as morning)
    • After 3:30pm: ANT REST getScripQuote (one token at a time, 1s apart)
  3. Join each row against gap-screener.csv to fetch stock LTP and 1st15m candle levels
  4. Evaluate success criteria
  5. Write back to CSV with EOD columns

Success Criteria

A trade is marked Result = true if either condition holds:

Condition Buy (CE) Sell (PE) Rationale
Option Profit EOD Quote > Morning Quote EOD Quote > Morning Quote Direct option price appreciation
Stock Breakout Stock LTP > 1st15m High Stock LTP < 1st15m Low Underlying confirmed the expected direction intraday (even if option retraced)

Output Columns (appended to gap_screener_option_quote.csv)

Column Type Description
Option Quote EOD number Live option price at EOD
Stock LTP number Stock price at EOD (from gap-screener.csv)
1st15m High number First 15-minute candle high (from gap-screener.csv)
1st15m Low number First 15-minute candle low (from gap-screener.csv)
Result true | false Trade success based on criteria above

Data Cleanup: If a stock's recommendation is removed/changed in gap-screener.csv after the morning run, that entire row is dropped from the EOD output. The CSV should only reflect stocks with current recommendations.

Error Handling

If a contract's EOD quote cannot be fetched (websocket timeout, REST error, post-session), the script logs a warning and skips that row.

Live Monitoring

Real-time trade activity monitoring without needing to parse the raw orchestrator.log by hand.

Script: monitor-gap.sh

Location & Invocation

./scripts/monitor-gap.sh        # Watch only new activity from now
./scripts/monitor-gap.sh -a     # Replay all activity + follow new

Purpose

Tails orchestrator.log in real-time and prints a human-readable narrative of GapStrategy's daily flow:

  • Gap check and PCR alignment logic
  • Buy entry execution
  • Live tick-by-tick P&L updates
  • Exit triggers (target, stop-loss, timeout)
  • GTT placement and fill events (order-side actors)

Why a Bash Script?

Unlike BulkPcrStrategy (which logs everything from its own class), GapStrategy's flow is distributed across multiple actors:

  • Zerodha's GTT placement → Zerodha.placeTargetStopLossGTT
  • Fill notifications → OrderBookkeeping._processTradeEvent
  • Poll-detected close → pollGttFills
  • GapStrategy's own logic → GapStrategy.ts / GapContract.ts

This script correlates lines from different actors by tracking the held contract symbol, filtering out noise, and highlighting critical events.

Technology

Pure bash + awk (mawk-compatible): No Node/tsc build, no network calls, zero ongoing cost. Runs forever in a terminal.

Log Message Filters

The script tracks and displays:

Filter Description
[GapStrategy] / [GapContract] All GapStrategy-owned logic
mentions GapStrategy Any log line mentioning "GapStrategy" by name
Held contract symbol Any line mentioning the currently-tracked option contract (even from order-side actors)
Zerodha.placeTargetStopLossGTT near GTT placement Broker's GTT target/stop-loss setup

Output Formatting

Key events are highlighted with *** markers:

  • TRIGGERED: GTT execution confirmed
  • executeTrade failed: Order placement error
  • Sell confirmed: Position closed
  • Outcome=: P&L summary (win/loss/timeout)
  • GTT poll: Poll-detected GTT status change
  • Decision: Technical analysis decision
  • TIMEOUT: Timeout-triggered exit

Note: orchestrator.log is truncated on every process restart (when npm run processes is restarted). The script uses tail -F (follow across truncate) so it keeps working through restarts.

Technical Details

In-depth information on implementation, dependencies, and integration points.

Contract Resolution Strategy

Why Local Contract Master?

AliceBlue's REST option-chain endpoint was confirmed live to return stale data (ltp=0, oi=0) for liquid names while the ANT mobile app showed real prices. The solution: local NFO contract-master JSON files.

Data Files

  • data/ant/NFO_contract.json – NFO (stock options) contract master (~18MB)
  • data/ant/BFO_contract.json – BFO (index options) contract master (~34MB)
  • Source: Official AliceBlue v2 format from https://v2api.aliceblueonline.com/restpy/static/contract_master/V2/
  • Re-download if stale (monthly advisable)

Resolution Logic

// For Buy recommendation (CE):
const candidates = allOptions
    .filter(o => o.optionType === 'CE')
    .filter(o => o.strike > spotPrice)
    .sort((a, b) => a.strike - b.strike);
const nearestOtm = candidates[0];  // Smallest strike above spot

// For Sell recommendation (PE):
const candidates = allOptions
    .filter(o => o.optionType === 'PE')
    .filter(o => o.strike < spotPrice)
    .sort((a, b) => b.strike - a.strike);
const nearestOtm = candidates[0];  // Largest strike below spot

Quote Collection: AntBatchQuote

Problem

Early iterations called ANT's REST OHLC endpoint once per symbol in a loop. Result: 429 (rate limit) errors.

Solution: Batch Websocket Subscribe

Shared helper src/tools/AntBatchQuote.ts subscribes to all resolved tokens at once via ANT's websocket, waits for first tick from each, then unsubscribes. Single websocket session, one roundtrip, parallel delivery.

Interface

// In GapScreenerOptionQuote.ts:
const pending = [
    { token: '12345', tradingSymbol: 'RELIANCE25OCT1100CE' },
    { token: '12346', tradingSymbol: 'INFY25OCT1500CE' },
    // ...
];
const quotes = await collectLiveQuotes(
    pending.map(p => p.token)
);
// returns: Map
const reliance_ltp = quotes.get('12345');  // 45.50

Timeout

Default: 3000ms (QUOTE_WAIT_MS). If a token hasn't ticked within this window, it's skipped with a warning.

POST-MARKET Quote Fetching

The Problem

AliceBlue's websocket only streams ticks during live market hours. After 3:30pm, subscribing times out with no data.

The Solution

In GapScreenerOptionQuoteEod.ts:

  • Before 3:30pm: Use websocket batch subscribe (same as morning)
  • After 3:30pm: Fall back to ANT REST getScripQuote (ScripDetails endpoint, not OHLC)
  • Polling rate: One token at a time, 1s apart (respect rate limits)

Important: Use ScripDetails endpoint (returns post-close LTP), not OHLC (returns null post-close).

Code Path

// In GapScreenerOptionQuoteEod.ts:
const now = new Date();
const hours = now.getHours();
const minutes = now.getMinutes();

if (hours >= 15 && minutes >= 30) {
    // Post-market: use REST ScripDetails
    for (const token of tokens) {
        const quote = await ant.getScripQuote(token);
        quotes.set(token, quote.ltp);
        await sleep(1000);  // 1s per call
    }
} else {
    // Intraday: use websocket batch
    const quotes = await collectLiveQuotes(tokens);
}

CSV File Locations

Critical Detail: All paths are anchored to process.cwd() (always the repo root when npm scripts or wrapper shell scripts run), NOT __dirname. In the compiled dist/ output, __dirname would be dist/tools/gapscreener/, putting CSVs in the build tree instead of alongside their source. This is why process.cwd() is used explicitly.

File Path Role
Gap Screener CSV src/tools/gapscreener/gap-screener.csv Input to morning option resolution; used in EOD for stock levels
Option Quote CSV src/tools/gapscreener/gap_screener_option_quote.csv Output from morning; input to EOD; final analysis output

Troubleshooting

gapscreener:generate Fails

Problem

Error: ENOENT ... /home/karthikeyan/tools/ohlc

Solution

External screener project not found or not set up. Verify:

ls -la /home/karthikeyan/tools/ohlc/
npm run start  # from that directory, does it work?

gapscreener:start – No Options Found

Problem

skipping SYMBOL: no CE/PE contract found in NFO contract master

Solution

  • NFO contract-master JSON is stale. Re-download from https://v2api.aliceblueonline.com/restpy/static/contract_master/V2/
  • Verify file exists: ls -la data/ant/NFO_contract.json
  • Check file size (~18MB). If smaller, download was incomplete.

gapscreener:start – Quote Timeouts

Problem

skipping SYMBOL: no live tick received for CONTRACT within 3000ms

Cause

ANT websocket never subscribed, or market data is not flowing.

Solution

  • Verify ANT session is active: GET /ant/connect (starts websocket) before running gapscreener:start
  • Check orchestrator.log for ANT connection errors
  • Verify market hours (NSE/NFO 9:15-15:30 IST)

gapscreener:end – Fails After 3:30pm

Problem

Timeouts or errors when running after market close.

Cause

Websocket subscribe doesn't work post-market. Script should have fallen back to REST, but may be failing to authenticate or fetch.

Solution

  • Ensure script is using ScripDetails endpoint (not OHLC)
  • Verify ANT session token is still valid: GET /ant/token
  • Check orchestrator.log for ANT REST call errors

monitor-gap.sh – No Output

Problem

Script starts but prints nothing even though GapStrategy is active.

Solution

  • Verify orchestrator.log exists and is being written: tail -f orchestrator.log
  • Verify npm run processes is running (check ps aux | grep orchestrator)
  • Try ./scripts/monitor-gap.sh -a to replay all activity (may reveal if log is old)

CSV Files Not Found

Problem

Error: gap-screener.csv not found at ...

Cause

Script was run from wrong directory (not repo root), or previous step failed without warning.

Solution

  • Always run from repo root: cd /home/karthikeyan/work/icici && ./scripts/gapscreener-morning.sh
  • Check that previous script in the pipeline ran successfully (check console output)
  • Verify files exist: ls -la src/tools/gapscreener/*.csv
